# X50 Patch Switcher: specification

Version 1 target. Owner: Mario Castro Squella. Written 2026-11-21.

## 1. Purpose

Chroma Noir's support keyboard player plays a KORG X50. The X50 holds 384 factory
combinations and 512 programs (plus 256 GM sounds) behind bank buttons, a number dial
and a small LCD, with category browsing but no search. On stage she needs a handful of
sounds per set, switched instantly and without hunting.

This app runs on her laptop, cabled to the X50 over USB, and does two things:

1. **Browse** (at home, rehearsal): find any sound by name, category or number, audition
   it on the X50, star favourites and arrange them into **sets**, one per setlist.
2. **Live** (on stage): a full-screen page of 6 or 8 large buttons, one per sound in the
   current set. Tap, key or foot pedal switches the X50.

It is a *selector*, not an editor or librarian. It never writes to the X50's memory.

It must work with **no network at all**: venues have poor connectivity, so this is a
desktop app, never a web app, and it has no network code.

### Non-goals for v1

- Editing sounds, writing to the X50, backing up its memory.
- Multi mode, the arpeggiator, drum kits as standalone selections, GM variation banks.
- The microX (identified and refused politely, §8).
- Hapax or DAW integration. The owner automates his own rig there; this app is for the
  keyboard player's standalone use.
- Network, update checks, telemetry, accounts, cloud sync.

## 3. Domain

### 3.1 Sounds

A **sound** is one selectable slot:

| Kind | Banks | Numbers | Canonical address |
|---|---|---|---|
| Combination | A, B, C | 000-127 | `COMBI A000` |
| Program | A, B, C, D | 000-127 | `PROG A000` |
| GM program | G | 001-128 | `PROG G001` |
| GM drum program | g(d) | 001-128 (9 used) | `PROG g(d)001` |

Address grammar accepted in search (case-insensitive, spaces optional): `A012`, `a12`,
`PROG A012`, `P A012`, `COMBI B100`, `C B100`, `cB100`, `G1`, `G001`, `gd1`, `g(d)001`.
A bare bank+number without a kind matches both the combination and the program at that
address. Numbers outside the bank's range are rejected, not clamped.

### 3.2 Catalogue

`data/x50-factory.tsv`, generated by `scripts/extract-voice-list.py` from VNL and checked
in. One row per sound: `kind`, `bank`, `number`, `name` (16 chars max, as printed),
`category` (as printed), and for programs the oscillator flag `s`/`d`/`D`/blank. Expected
counts: 384 combinations, 512 programs, 128 GM, 9 GM drum kits. Edit the script, never
the file.

**Names from the unit** (§6) overlay the factory names per slot, with the date they
were read. A slot whose unit name differs from the factory name is marked *edited*.

### 3.3 Library

One JSON file, `library.json`, in the config directory (§7.4). Contains:

- `favourites`: set of canonical addresses.
- `sets`: ordered list of `{ id, name, size (6|8), slots: [ { address, label? } × size ] }`.
  Empty slots are `null`. `label` overrides the button text (for example the song name);
  the sound name is still shown smaller underneath.
- `currentSetId`.
- `recents`: up to 50 `{ address, count, lastUsed }`.
- `unitNames`: `{ address: { name, category?, readAt } }` from the last read.
- `unit`: `{ memberCode, version, globalChannel, bankMap, lastSeen }` from the last probe.

Writes are atomic (`QSaveFile`) and debounced 500 ms. A file that fails to parse is
renamed `library.json.broken-<timestamp>` and the app starts empty, saying so once.

## 4. Behaviour

### 4.1 Browse view (default)

- **Search box** at the top, focused on start. Multi-token AND; accent- and
  case-insensitive; an address token (§3.1) filters by address; `cat:<text>` filters by
  category prefix. Results update as you type.
- **Kind filter**: three toggles, Combis / Programs / GM, all on by default.
- **Category list** on the left: the 16 combination categories or the 16 program
  categories (from VNL; from the unit once read), plus "All".
- **Result list**: address, name, category, star, *edited* marker, recents count.
  Highlight never sends. **Enter, double-click or the Play button sends.**
- **Prev/next** (`Ctrl+Left/Right`, `PgUp/PgDn` when the list does not have focus) step
  through the current result list and send.
- **Star** toggles favourite (`Ctrl+D` or click).
- **Add to set**: `Ctrl+1`…`Ctrl+8` puts the highlighted sound in that slot of the
  current set; also via context menu.
- **Set editor** panel: the current set's slots as a grid matching the live layout,
  drag to reorder, double-click to edit the label, `Del` to empty a slot. Set picker,
  New / Rename / Duplicate / Delete (delete asks).
- **Display strip** at the top: what the X50 is on now (kind, address, name), as last
  sent or as followed from the panel, and the connection state.

### 4.2 Live view

Entered with `F5` or the Live button; full screen.

- A **2 × 3 or 2 × 4 grid** of large buttons (per the set's `size`). Each shows the
  slot number, the label (or the sound name) large, and the address and sound name
  small. Empty slots are drawn dim and do nothing.
- The **current** sound's button is lit. If the X50 is on a sound not in the set
  (changed on the panel), no button is lit and the top bar shows what it is on.
- **Input**:
  - Click or touch a button: send.
  - Keys `1`…`8`: send that slot.
  - `Right`, `Down`, `Space`, `PgDn`: next slot (skips empty slots; stops at the last,
    no wrap). `Left`, `Up`, `PgUp`: previous. This makes common USB page-turner foot
    pedals work, since they send arrow or page keys.
  - Pressing the current slot again re-sends it (a recovery move, never harmful).
  - `Ctrl+Left/Right` (or `[` / `]`): previous / next set.
- **Leaving live view** needs `Esc` held for 1 s, or `Esc` twice within 1 s, so a
  stray key on stage cannot drop her out. A small hint says so.
- **Top bar**: set name, connection LED and text (`X50 CONNECTED` / `NO X50`), the
  X50's current mode as known (`PROG` / `COMBI`).
- No dialogs, toasts or focus changes ever appear in live view. Errors show in the top
  bar only.
- The window does not sleep the display while in live view (Qt has no API; on Windows
  `SetThreadExecutionState(ES_DISPLAY_REQUIRED | ES_CONTINUOUS)` while live, cleared on
  exit; no-op elsewhere).

### 4.3 Sending (both views)

Exactly the sequence in `docs/MIDI.md` §3: optional Mode Change (only when the target's
kind differs from the believed mode), then CC0, CC32, PC on the global channel, with
the bank values for the X50's Bank Map. The app sends only on an explicit action (§4.1,
§4.2), never on highlight.

Believed state comes from, newest wins: the app's own last send, the Mode and State
reply (§5 of MIDI.md), incoming panel changes and `4E` (follow mode). If the mode is
unknown (no reply yet), the app sends the Mode Change anyway.

A send to a disconnected port does nothing except flash the status red.

### 4.4 Follow the panel

Incoming CC0/CC32/PC on the global channel and `4E` mode changes update the display
strip and the lit button. Echoes of the app's own send within 300 ms are ignored.

### 4.5 Connection and probing

- Settings: MIDI **output** and **input** port (picked from lists, stored by name,
  substring match on reconnect), with a **Test** button that sends a probe.
- On connect, and from the **Check X50** button, the app runs the **probe**:
  Device Inquiry → learn member code, version, global channel; then Mode and State →
  learn mode, Bank Map, the three enable flags, current program and combination.
- The probe's result is a **checklist** (settings dialog and `--probe` output):
  `✓ X50 found (system 1.05, global channel 1)` ·
  `✓ Program Change enabled` · `✗ Bank Change disabled: GLOBAL 1: MIDI, tick "Bank"` ·
  `✓ Combination Change enabled` · `✓ Bank Map: GM` · `SysEx: replies received`.
  Every ✗ line says where to fix it on the X50, in words from the X50's own pages.
- If the Device Inquiry gets no reply in 1 s: `No reply. Is the X50 on, the USB cable
  in, and GLOBAL 1: MIDI "Exclusive" ticked?` The app still works for sending with a
  manually chosen channel (default 1) and a manually chosen Bank Map (default GM).
- While disconnected, one 2 s poll re-scans ports. No other timers.

### 4.6 Read names from the X50

Button in browse view (never available in live view). Requests program banks A-D,
combination banks A-C and the global dump (category names), one at a time, with a
progress bar and Cancel; 10 s timeout per bank; a NAK or a malformed dump stops the
read and reports which bank and why. Results go to `unitNames`. Takes a few seconds
over USB.

## 5. Footprint

- Idle CPU 0 %. No timer under 2 s, and that one only while disconnected (plus the 1 s
  Esc-hold timer while Esc is down, and request timeouts while a request is pending).
- No repaint without a state change. Live buttons are repainted only when the lit
  button or the connection state changes.
- Resident memory under 60 MB on Windows after start.

## 6. Command line

| Flag | Does |
|---|---|
| `--list-ports` | print output and input port names, exit 0 |
| `--port <substr>`, `--in-port <substr>` | override the saved ports |
| `--channel <1-16>` | override the global channel |
| `--send <address>` | send one sound and exit (0 ok, 2 bad address, 3 no port) |
| `--probe` | run the probe, print the checklist, exit 0 if all ✓ else 1 |
| `--diagnose <dir>` | probe, then read every bank, write `report.txt` and raw `.syx` captures to `<dir>`, exit |
| `--fake-midi` | use the `FakeX50` backend (tests, screenshots, demos) |
| `--config-dir <dir>` | use another config directory |
| `--screenshot <png> [--screenshot-state <name>]` | render a view headless and exit |

`--diagnose` matters most: it is how the owner gets real data from a unit he does not
have. The Windows zip ships `Diagnose X50.bat`, which runs it into a folder on the
desktop, so the keyboard player can double-click it and send the folder back.

## 7. Windows specifics

1. Portable zip, built by `windeployqt`; unzip anywhere and run. No installer, no admin.
2. If a file named `portable` sits next to the exe, the config directory is the exe's
   folder (for a USB stick); otherwise `QStandardPaths::AppConfigLocation`.
3. The WinMM port name of the X50 is not known yet; the app never hard-codes it. The
   picker shows every port; `--list-ports` output from gate G1 goes in `docs/MIDI.md`.
4. WinMM opens a port exclusively. If KORG's editor or a DAW holds the X50's port, the
   open fails: the status must say "port busy (another program is using the X50)".
5. Unsigned exe: SmartScreen warns on first run. The README and the one-page guide say
   "More info → Run anyway". Code signing is out of scope for v1.

## 8. Identification

Device Inquiry member code `01` = X50 (supported). `09` = microX: the app says "This is
a microX; X50 Patch Switcher supports the X50 only" and does not send. Any other reply,
or none: the app works in manual mode (§4.5) and says it could not confirm an X50.

## 9. Architecture

```
src/core/   SoundAddress, Catalogue, SearchQuery, Library, SetModel   (no Qt GUI, no MIDI)
src/midi/   MidiBackend (interface), RtMidiBackend, FakeX50,
            X50Protocol (pure: build requests, parse replies, 7/8 codec),
            X50Link (state machine: probe, send, follow, read names)
src/ui/     MainWindow, BrowseView, SetEditor, LiveView, DisplayStrip,
            SettingsDialog, ProbeChecklist, Theme
src/app/    main.cpp, CommandLine
```

- `X50Protocol` is pure functions over byte vectors: every byte in `docs/MIDI.md` is
  produced or parsed here and nowhere else, and each has a test with the exact bytes.
- `X50Link` lives on the GUI thread; RtMidi callbacks arrive on RtMidi's thread and are
  marshalled with a queued signal. SysEx replies are matched to pending requests with
  timeouts; nothing blocks.
- `FakeX50` implements the X50's side of every message in `docs/MIDI.md` so the whole
  app, including `--diagnose`, runs headless in tests and CI.
